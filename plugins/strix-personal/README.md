# Strix Personal

**Execution control for the agents you use every day.**

Install Strix → scan your project → govern the actions that matter → prove what
Claude (or any agent) was allowed to do.

Strix Personal is a Claude Code plugin. It scans your repository for
consequential actions (payments, deletes, sends, schema migrations, AI
tool-use), wraps the risky ones with `governed_action()`, tests that the wrap
actually governs, and produces **signed receipts you can verify independently**
— no trust in the agent, the plugin, or Strix required.

> The plugin **renders** proof; it never **determines** it. It may detect,
> propose, patch, test, and explain — it will never silently approve an action,
> weaken a policy, fabricate a receipt, or claim coverage it didn't establish.

## Install

```text
/plugin marketplace add Tarshann/solo-builder-core
/plugin install strix-personal@strix
```

The plugin is **zero-install** — it bundles its own stdlib-only scanner and
helpers, so you do not need to `pip install` anything to scan and wrap.

## Commands

| Command | What it does |
|---|---|
| `/strix-personal:strix-scan` | Read-only inventory of consequential actions + coverage. |
| `/strix-personal:strix-plan` | Capability map + proposed controls + which call sites to wrap. |
| `/strix-personal:strix-apply` | Wrap one call site — rollback-safe, diff shown + confirmed before write. |
| `/strix-personal:strix-test` | Allowed / approval-required / bypass scenarios; verify the receipt. |
| `/strix-personal:strix-status` | Where every action sits on DETECTED → … → VERIFIED. |

Plus an **`execution-control`** skill (assessment + education only — no
enforcement) for "what is execution control / which of my actions are risky".

## The lifecycle

```
DETECTED → WRAPPABLE → WRAPPED → TESTED → ENFORCED → VERIFIED
                                                  └→ SUPPRESSED (# strix: allow)
```

Detection is **not** enforcement. A scan can place an action no further than
`WRAPPED`; `TESTED` / `ENFORCED` / `VERIFIED` each require a real runtime signal
(a passing test, a passing bypass check, a signed evidence record). The plugin
will never describe a merely-detected action as governed.

## Free vs hosted

- **Local (free, no account):** scan, wrap, deny/approval/bypass tested, local
  Ed25519-signed receipts, offline verification with `npx @strixgov/verifier`.
- **Connected Mode (paid, self-serve):** set `STRIX_API_KEY` + `STRIX_TENANT_ID`
  — same code, additive behavior — for hosted approvals, receipt history,
  public proof URLs, cross-service aggregation, and compliance attestation.

No code changes between the two. Connected Mode forwards already-signed receipts
to the hosted kernel; it does not gate local execution.

## Manual wrap (when a call site is multi-line)

`/strix-apply` refuses to auto-wrap multi-line or ambiguous call sites — wrap
them by hand under review:

**Python**
```python
from strix_wire import governed_action  # Strix Personal

result, _evidence_id = governed_action(
    capability_id="payment.charge",
    payload={"amount": amount, "currency": "usd"},  # non-secret params only
    operation=lambda: stripe.Charge.create(amount=amount, currency="usd", source=token),
)
```

**TypeScript**
```typescript
import { governedAction } from "./governedAction"; // Strix Personal

const { result, evidenceId } = await governedAction(
  { capabilityId: "payment.charge", payload: { amount, currency: "usd" } },
  async () => await stripe.charges.create({ amount, currency: "usd", source: token }),
);
```

## Provenance

The bundled `scripts/_vendor/` modules and `helpers/` are **byte-identical
copies** of the tested sources in `solo-builder-core`
(`src/solo_builder/action_scanner.py`, `src/solo_builder/strix_personal/*`,
`.claude/skills/strix-wire/helpers/*`). They are regenerated by
`scripts/sync_strix_personal_plugin.py` and locked against drift by
`tests/test_strix_personal_plugin_parity.py`. Do not edit the vendored copies
directly.
